# Устранение дубликатов событий из разных источников

Evently собирает афишу из нескольких источников (KudaGo, Timepad). Одно и то же событие часто
публикуется в нескольких местах — и пользователь видел бы его в ленте дважды и больше.
Механизм дедупликации находит такие события и показывает каждое один раз.

## Как это работает

Запускается автоматически после каждого импорта данных парсера
(`apps/server/src/modules/dedup/`).

1. **Блокировка.** Сравниваются только события одного города, у которых есть сеанс в один и тот же день,
   и только из *разных* источников. Это сокращает число сравнений на порядки:
   6 351 событие → 156 тыс. пар вместо ~20 млн.
2. **Название.** Нормализация: регистр, «ё/е», возрастная маркировка («12+»), знаки препинания,
   служебные слова («концерт», «экскурсия», «балет»…), название площадки внутри заголовка.
   Похожесть — максимум из доли общих слов, вхождения короткого названия в длинное
   и коэффициента Дайса по триграммам (устойчив к падежам: «Щелкунчик» / «Щелкунчика»).
3. **Площадка.** По координатам: до 200 м — совпадение, до 500 м — частичное.
   Без координат — по похожести названия площадки.
4. **Время.** Ближайшие сеансы: разница до 15 минут — совпадение, до часа — частичное.
5. **Решение.**

   `оценка = 0,5 · название + 0,3 · площадка + 0,2 · время`

   Дубликат, если оценка ≥ 0,75 **и** похожесть названия ≥ 0,6
   (в одном зале в одно время могут идти разные события — без похожего названия не склеиваем).
6. **Группы и основное событие.** Пары объединяются в группы. Основным становится событие
   с наибольшим числом сеансов (чтобы не потерять даты), затем — с самой полной карточкой
   (картинка, ссылка на билет, цена, описание). Остальным проставляется `duplicateOfId`,
   и лента, каталог и AI-ассистент их не показывают.

Разметка пересчитывается при каждом импорте: если источник исправил данные, пометка снимается.

## Результаты на реальных данных (17.10.2026)

| Показатель | Значение |
| --- | --- |
| Актуальных событий | 6 351 (KudaGo + Timepad, 17 городов) |
| Сравнено пар | 156 283 |
| Найдено дубликатов | 35 в 9 группах |
| Ложные склейки при ручной проверке всех групп | 0 |

Основной источник дубликатов — экскурсии: Timepad публикует каждую дату отдельным событием,
KudaGo — одним событием со всем расписанием. Например, «Обзорная экскурсия по Санкт-Петербургу
с посещением Эрмитажа» раньше давала в выдаче 11 карточек, теперь одну (80 сеансов).

Источники пока пересекаются мало (KudaGo — в нескольких крупных городах), поэтому дубликатов
немного; с подключением новых источников доля будет расти, а механизм уже готов.

## Как получить актуальные цифры

```
pnpm --filter @evently/server exec tsx src/scripts/dedup-stats.ts
```

## Настройка

Веса, порог и стоп-слова — константы в начале `apps/server/src/modules/dedup/dedup.match.ts`.
