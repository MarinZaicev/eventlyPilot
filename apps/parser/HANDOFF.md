# Evently / afisha-parser — передача проекта новому чату

> Этот файл — для нейросети, которая продолжает работу. Прочитай его целиком перед первым ответом.
> Версия парсера на момент написания: **0.5.7** (24.10.2026).

## 1. Что это за проект

**Evently** — мини-приложение афиши для мессенджера **MAX** (16 городов России). Делают двое:

| Кто | Что | Где |
|---|---|---|
| Пользователь (ты работаешь с ним) | **Python-парсер** `afisha-parser`: собирает события, кино, заведения, трейлеры → JSON-файлы | сервер `matataserver` |
| Друг пользователя | БД (PostgreSQL + Prisma), бэкенд (Fastify, TypeScript), фронтенд (React + Vite, MAX Mini App) | тот же сервер |

Бэкенд друга **читает файлы парсера прямо с диска** (`PARSER_OUTPUT_ROOT=/home/matatik/afisha-data/output`),
модуль `apps/server/src/modules/parser-sync/`. HTTP-отправка из парсера (`publisher.py`) не используется.

Проект участвовал в хакатоне (презентация уже сделана, в ней остались плейсхолдеры: Git, хеш коммита,
адрес API, имена команды — их заполняет пользователь).

## 3. Как устроен парсер

```
src/afisha_parser/
  __main__.py      CLI: daemon, run, status, resume, fetch, cinema, places, trailers-report, ...
  config.py        все настройки (AFISHA_* из .env), pydantic-settings
  cycle.py         один цикл службы и daemon; status.json; пауза источников; параллельно по источникам
  pipeline.py      сбор событий одного источника/города; source_client() — HTTP-клиент с лимитом/час
  http_client.py   паузы, повторы (429 для источников НЕ повторяется), счётчик запросов
  pauses.py        после 401/403/429 источник на паузу (output/source_pause.json); resume снимает
  cities.py        16 городов: slug, часовой пояс, центр, код KudaGo (у KudaGo только 10 из 16)
  models.py        контракт универсального дампа событий (Event, EventBatch), SCHEMA_VERSION 1.1
  timefilter.py    отбрасывание прошедших событий/сеансов
  images.py        скачивание картинок, имя = SHA-256, индекс images/index.json
  retention.py     уборка старых снимков, raw, ненужных картинок и трейлеров
  sources/         kudago.py, timepad.py (события); places_kudago.py, osm.py (заведения);
                   cinema_kudago.py (фильмы и сеансы)
  enrichers/       title_guess.py (название фильма из заголовка), tmdb_trailers.py (TMDb),
                   tmdb_catalog.py (прокат TMDb), kinopoisk.py (ПоискКино API — запасные трейлеры)
  exporters/evently.py   формат Evently (camelCase) для бэкенда
  places.py / places_cycle.py   заведения «где поесть»
  cinema.py / cinema_cycle.py   кино: фильмы + сеансы; ещё и как события Evently
  trailers.py      скачивание роликов yt-dlp (+прокси), отчёт trailers-report
  preview.py       страница output/preview/trailers.html для просмотра трейлеров глазами
```

Тесты: `tests/` (148 штук). `conftest.py` изолирует тесты от настоящего `.env` и выключает
лимит запросов, заведения и кино (их тесты включают сами). Запуск: `pip install -e ".[dev]" && pytest`.

## 4. Что лежит в output/ и кто это читает

| Путь | Что | Читает |
|---|---|---|
| `status.json` | итог цикла; `targets[]` с `source`, `city`, `ok`, `fresh` | бэкенд: импорт по `finished_at`, архивирует пропавшие события только при `fresh && ok` |
| `evently/<источник>/<город>/latest.json` | события в формате Evently (`events[]`, поле `occurrences`) | бэкенд: **все папки** в `evently/` считаются источниками событий |
| `evently/kudago-cinema/<город>/` | фильмы кинотеатров как события (`externalId` = `<город>-<id фильма>`) | бэкенд, без доработок |
| `movies/<источник>/<город>/latest.json` | трейлеры к событиям (`event_source`, `event_source_id`, `trailer{...}`) | `movie-sync.service.ts` (пропускает только `movies/tmdb`) |
| `movies/tmdb/ru/latest.json` | прокат TMDb (общероссийский) | парсер (сверка), страница трейлеров |
| `app/places/<город>/latest.json` | заведения, camelCase, источники склеены, `contentHash` | бэкенд — через набор `evently-friend-kit` (ещё не внедрён) |
| `app/cinema/<город>/latest.json` | фильм → кинотеатры → сеансы | бэкенд — по желанию |
| `events/`, `places/`, `cinema/` | универсальные дампы (snake_case) | для отладки и повторного экспорта |
| `images/`, `images/index.json` | картинки; бэкенд маппит URL → файл → `/media/events/...` | бэкенд |
| `trailers/<id>.mp4` | скачанные ролики (если включено) | бэкенд через `/media/trailers/...` (в наборе для друга) |
| `cache/kinopoisk.json` | кеш Кинопоиска и счётчик запросов за сутки | парсер |

**Не класть в `evently/` и `movies/` ничего, кроме событий и трейлеров к событиям** — бэкенд импортирует всё подряд.

## 5. Источники и их правила (важно — уже были баны)

- **KudaGo** public API v1.4: события, заведения (`/places/`), кино (`/movies/`, `/movie-showings/`).
  В начале октября 2026 KudaGo отдавал 403 даже из обычного браузера, потом IP разбанили.
  Только российские IP. **Сеансы `/movie-showings/` могут быть заброшены** — не проверено.
- **Timepad** API v1, токен Bearer. Аккаунт уже блокировали за нагрузку, пользователь нашёл новый токен.
  Проверка токена: `curl -s "https://api.timepad.ru/introspect?token=$TOKEN"` → `"active": true`.
- **TMDb** v3 — фильмы, ролики, прокат. **ПоискКино** (`api.poiskkino.dev`, заголовок `X-API-KEY`,
  бесплатно 200 запросов/сутки) — запасные трейлеры.
- **OpenStreetMap / Overpass** — заведения. Лицензия ODbL: в приложении обязательна подпись
  «© участники OpenStreetMap».
- **Киноафиша** — открытого API нет; написан черновик письма в info@kinoafisha.info.
  Парсить сайт без их разрешения не стали.

**Бережный режим (с 0.4.3), не ослаблять без причины:** не больше `AFISHA_REQUESTS_PER_HOUR` (30)
запросов в час к каждому источнику, не больше `AFISHA_MAX_PAGES` (20) страниц на город, отказ
401/403/429 → пауза источника на 24 ч по всем городам. У пользователя в `.env`
`AFISHA_INTERVAL_MINUTES=360`. Он просил «большую подушку, чтобы не забанили».

## 6. Текущее состояние (на 17.10.2026)

Сделано в 0.5.0, **на сервере ещё не проверено на живых данных**:
- заведения (KudaGo + OSM), кино KudaGo (фильмы и сеансы → события Evently), трейлеры из TMDb
  (все языки) и Кинопоиска, прокси для yt-dlp, команды `places`, `cinema`, `trailers-report`;
- набор для бэкенда друга `evently-friend-kit.zip`: модель `FoodPlace` + миграция, импорт заведений,
  `/api/places`, раздача `/media/trailers` с Range, правки для показа скачанного ролика.

Последняя проверка с сервера (17.10, до установки 0.5.0):
- все запросы к KudaGo вернули **не JSON** (пусто или HTML) — нужно посмотреть код ответа: снова бан,
  таймаут или что-то ещё. Команда — в разделе 8;
- Overpass `/api/status` через голый curl → **406** (скорее всего, отказ для User-Agent curl;
  парсер шлёт свой UA — проверить);
- YouTube с сервера **недоступен** (таймаут) → для скачивания трейлеров нужен `AFISHA_TRAILERS_PROXY`
  (у пользователя есть свои VPN-серверы).

18.10.2026: KudaGo снова отдаёт **403** (nginx) — источник на паузе, работает на старых данных.
Поэтому в 0.5.1 кино берётся из **Кинопоиска** (`ticketsOnSale` + премьеры) и раскладывается событиями
`kinopoisk-cinema` по всем 16 городам; заведения — из OSM во всех городах, где KudaGo не собрался.
Жалоба пользователя, которую это решает: «фильмов мало, и в основном советские» (раньше кино в ленте
было только из разовых ретро-показов KudaGo/Timepad). Скрипт `update.sh` теперь ищет zip в
`~/projects/parser` (пользователю так удобнее). Скачивание файлов трейлеров отложено.
Не проверено на живом API: формат фильтров ПоискКино (`ticketsOnSale=true`, `premiere.russia=дд.мм.гггг-дд.мм.гггг`,
повтор `type`/`selectFields`) — если API ответит 400, текст ошибки будет в `status`.

18.10, первый полный цикл 0.5.1 (4,5 ч): Timepad ок во всех городах (msk/spb упёрлись в 2000 событий),
OSM — ~30 тыс. заведений, KudaGo на паузе, **Кинопоиск ответил 403** во время цикла, хотя вручную тот же
токен работает (`ticketsOnSale=true` → 122 фильма). В 0.5.2 Кинопоиск идёт первым в цикле, текст отказа
пишется в status, есть `python -m afisha_parser cinema --source kinopoisk --force`.

18.10, 0.5.2 на сервере: Кинопоиск отдал 122 в прокате + 39 премьер, ролики у 82 из 161 (в основном из TMDb).
0.5.3: догрузка роликов из полных карточек Кинопоиска (40/сутки, кеш), исключены театральные трансляции.
**Главная цель пользователя: как можно больше фильмов с трейлерами, а в будущем — точно, в каком кинотеатре что идёт.**
Сейчас сеансов по кинотеатрам нет ни из одного источника (KudaGo забанен; список Кинопоиска — общероссийский).

22.10: друг жаловался «в ленте почти только кино, остальное пропало». Причина в парсере (исправлено в 0.5.5):
Timepad брал события от дальних к ближним, и лимит 20 страниц в msk/spb срезал **ближайшие** дни, а бэкенд
архивировал их как пропавшие (цель timepad fresh+ok). Теперь два прохода: ближайшие по возрастанию даты
(лимит режет конец месяца) + до 3 страниц уже идущих (выставки). Также на стороне друга: категории
у событий kinopoisk-cinema могли не обновиться при upsert, и архивные события должны возвращаться в ACTIVE.

24.10, 0.5.6: в ленте всё ещё много кино → Кинопоиск ограничен: 40 самых популярных в прокате + 15 ближайших
премьер, без перевыпусков старше 2 лет (AFISHA_CINEMA_MAX_*). KudaGo — свой лимит `AFISHA_SOURCE_LIMITS=kudago:10`
(раз в 6 минут); пользователь просил KudaGo **не отключать** (события, кино и заведения) — это главный источник.

24.10, 0.5.7: цель — «фильм идёт в городе + ссылка на покупку». Решили к сроку: популярные фильмы
Кинопоиска во всех городах, `ticketUrl` = `kinopoisk.ru/film/<id>/afisha/city/<номер>/` (сеансы и билеты
в этом городе). Номера городов Кинопоиска: msk 1, spb 2, smr 11 (в `cities.py`), остальные — через
`AFISHA_KINOPOISK_CITY_IDS` или в `cities.py`, когда пользователь их пришлёт. Дальше (пользователь
согласен на всё ради точности): сеансы по кинотеатрам — открытая выгрузка «Киномакса»
(kinomax.ru/static/api, с сервера отвечает 302 — проверить, куда), ответ Киноафиши, KudaGo (всё ещё 403).

## 7. Как работать с пользователем

- Язык — русский. Пользователь не программист-бэкендер: давай **готовые команды целиком**, по шагам,
  и объясняй, что должно получиться.
- Ты не видишь сервер: пользователь сам запускает команды и присылает вывод (часто файлом).
  Российские сайты (KudaGo, Timepad, Киноафиша) из песочницы нейросети обычно недоступны —
  проверяй их командами на сервере, не гадай.
- **Секреты:** никогда не проси прислать токены и `.env` целиком. Токен читать в переменную:
  `TOKEN=$(grep '^AFISHA_TIMEPAD_TOKEN=' ~/afisha-data/.env | cut -d= -f2-)` — и не печатать.
  В README/Git/презентацию секреты не класть.
- Новую версию отдавай zip-архивом всего `afisha-parser/` (без `output/`, `.env`, `__pycache__`),
  повышай версию в `src/afisha_parser/__init__.py` и `pyproject.toml`, гоняй тесты.
- Чужой код (бэкенд друга) менять отдельными файлами + инструкцией: его версия у нас может быть старой.
- Трейлеры-файлы — юридически серая зона (права прокатчика, условия YouTube), скачивание по флагу.

## 8. Полезные команды (на сервере)

```bash
cd ~/afisha-data && source ~/.venvs/afisha-parser/bin/activate
python -m afisha_parser status            # итоги цикла, паузы, запросы по источникам
journalctl -u afisha-parser -n 100 --no-pager
python -m afisha_parser resume kudago     # снять паузу после отказа
python -m afisha_parser cinema --city msk --force
python -m afisha_parser places --city omsk --force
python -m afisha_parser trailers-report
python -m afisha_parser trailers-page     # output/preview/trailers.html
sudo systemctl restart afisha-parser

# Что отвечает KudaGo (код + начало ответа)
curl -s -m 20 -A "afisha-parser/0.5" -o /tmp/k.txt -w "%{http_code}\n" \
  "https://kudago.com/public-api/v1.4/events/?location=msk&page_size=1"; head -c 300 /tmp/k.txt; echo
```
